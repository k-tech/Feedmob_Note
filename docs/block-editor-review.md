# Block 编辑器审查与修复记录

审查日期：2026-09-08。

本轮目标是让现有块编辑路径可靠、容易理解：输入、选择类型、调整顺序、分栏、撤销、保存和切换日期。交互基准参考 [Notion 写作与编辑基础](https://www.notion.com/help/writing-and-editing-basics) 与 [块基础](https://www.notion.com/nb/help/guides/block-basics-build-the-foundation-for-your-teams-pages)。不将当前产品描述为 Notion 完整复刻。

## 已修复的问题

| 问题 | 原行为及影响 | 修复 |
| --- | --- | --- |
| 保存回包覆盖编辑 | 父组件把保存结果重新作为初始内容下发，重设正文、标题、标签与光标；保存中输入可能丢失 | 一个编辑器实例只负责一份已加载文档；回包只确认提交的快照，后续修改继续保留 |
| 日期/用户请求串线 | 旧日志仍在状态里时就挂载新日期编辑器；慢请求可能覆盖新日期 | 以用户和日期标识加载结果，取消过期请求，加载完成后才挂载对应编辑器 |
| 保存失败误报成功 | HTTP 错误或异常被吞掉，仍显示保存时间 | 非成功状态向编辑器抛错，显示重试信息；阻止重复提交 |
| 切走未提交日志 | 未提交修改仅在内存中 | 按用户和日期保存浏览器本地草稿；恢复最新草稿；提交成功仅清理对应快照 |
| 保存不完整 | 正文、清理标签、创建标签分别执行，后续失败仍保留部分写入 | 全部放入同一 Prisma 事务；标签统一清洗、去重 |
| 无效初始数据 | JSON 字符串直接交给编辑器，历史空文本节点可能报错 | 初始化前解析 JSON、清理历史空文本；格式错误明确显示加载失败 |
| Slash 输入不同步 | 依靠 keydown/textInput 猜测正文，中文输入、粘贴和选区变化不同步 | ProseMirror 插件从已提交事务推导查询和有效范围 |
| Slash 回车冲突 | 全局捕获回车，抢输入法候选确认；后续编辑器快捷键又执行 | 输入法事件保留原生行为；菜单只处理当前编辑器的导航键并阻止重复分发 |
| 模板/分栏生成非法节点 | 创建 `text: ''` 的文本节点 | 使用合法的空 paragraph；16 项 Slash 操作全部校验 schema 与撤销 |
| Slash 操作拆成两步 | 先删查询，再转换/插入；失败可能只删除指令 | 查询删除与转换共用事务；列表中的标题/文本转换与块菜单共用逻辑 |
| 块粒度不一致 | 键盘复制待办时仅复制里面的段落；鼠标与键盘目标不同 | 列表项连同勾选状态和嵌套内容作为一个块操作 |
| 移动改变光标或产生补位段落 | 先删必需子节点导致 schema 自动补段落 | 原子交换兄弟块并保留光标偏移 |
| 分栏留下空栏或误删 | 移出最后一个块后自动补空段落；祖先被拖入自身子节点 | 移除腾空的列，映射位置后校验目标；失败不提交任何事务；拒绝祖先/后代互拖 |
| 侧向拖拽没有反应 | 只有按住 Shift 才计算左右落点，普通拖拽不会显示竖向蓝条，和 Notion 的上手逻辑相反 | 左右中部最大 120px 作为分栏热区（窄列最多三分之一），列间空隙单独识别，上下边缘优先纵向插入；蓝线、高亮和文字共用实际目标；无效落点不显示指示 |
| 拖拽状态污染 | 全局 window 保存位置，跨编辑器、文档变动后仍可能沿用 | 每个 EditorView 独立维护拖拽快照；正文变化立即使旧拖拽失效 |
| 左侧手柄难点到 | 鼠标穿过编辑区与手柄间距时立即隐藏 | 给跨过间距留短暂宽限；添加可访问名称 |
| 白板偏移和撤销不同步 | 用 CSS 像素直接绘制固定 960px 画布；图片只在首次加载 | 按画布与显示尺寸换算坐标，使用 Pointer Events；按节点属性恢复撤销；箭头真正带箭头 |
| 图表/嵌入显示旧内容 | 本地组件状态没有跟随节点属性变化 | 属性变化同步预览和输入，包含撤销/重做 |
| 嵌入类型识别错误 | 对整个 URL 做子串匹配，伪域名也被识别；无协议校验 | 解析 URL 和 hostname；支持 YouTube、Loom、Figma 与 MP4；无效协议显示错误 |
| 浮动格式栏销毁后回调 | 第三方 tooltip 的延迟 focus 回调在编辑器卸载后仍执行 | 改为独立选区格式栏，生命周期内监听并清理，不留延迟回调 |
| 样式缺口 | Tailwind reset 后普通列表缺标记；代码块嵌套 code 背景不一致 | 补列表、链接、代码样式；空文本和空标题显示提示；窄屏分栏纵向排列 |

## 当前交互规则

- 从标题按 Enter/↓ 进入正文；正文输入 `/` 搜索中文、英文或拼音关键词。
- Slash 优先排列文本、标题和列表。↑/↓ 选择、Enter 执行、Escape 关闭；输入法候选确认不会执行指令。
- `+` 在下方加块并打开类型选择；Alt+点击在上方添加。在列表中添加新的列表项。
- 块菜单支持文本、标题、列表、待办、引用、提示块和代码块之间的转换。列表项转换保留相邻项与嵌套内容。
- Alt+↑/↓ 移动当前块；Ctrl/Cmd+D 复制；Ctrl/Cmd+Z 撤销。
- 拖到块的上/下半区调整顺序；拖到左/右边缘会出现竖向蓝条，松手后创建或扩展分栏，不需要按 Shift。菜单也可以创建或解散分栏。
- 自动保存的是**此浏览器的本地草稿**；“提交工作日志”或 Ctrl/Cmd+Enter 才写入服务端。

## 代码结构

- `BlockEditor.tsx`：文档编辑、快照提交及本地草稿协调。
- `extensions/SlashCommand.ts` + `useSlashCommand.ts`：文档事务中的指令状态与 React 定位。
- `SlashCommandMenu.tsx`：指令目录、筛选和键盘菜单。
- `SelectionToolbar.tsx`：选区格式操作与定位。
- `utils/block-conversion.ts`：保留内容的块类型转换，供菜单和 Slash 共用。
- `utils/block-movement.ts`：位置解析、复制、移动、分栏与事务校验。
- `utils/block-drag.ts`：按编辑器隔离的拖拽生命周期。
- `utils/document.ts` / `embed-url.ts`：文档解析、快照和外部链接规范化。

## 2026-10-14 分割线与拖放复查

本轮暂停 REA，仅审查本项目源码并在隔离的本地编辑器中复现操作。审查覆盖块 schema 默认值、斜杠菜单、块选择、转换、移动、复制、删除、列清理、文档读取和草稿/偏好存储。

- 根因：ToggleNode 的优先级 1101 高于段落，改变了 ProseMirror 的默认块。原生分割线命令用默认类型的 `create()` 补尾块，生成缺少必需标题段落的 toggle，并构造无效 TextSelection。将键盘优先级移至独立扩展，保留段落作为默认块；旧数据中的缺失折叠标题会补成空段落，保留原有正文和属性。
- 分割线及其他原子块被选中后，Enter 复用下方已有文本块；没有文本块时创建可输入段落。
- 左右外侧均提供输入区域；侧向识别范围为宽度的 20%，最大 120px，窄列最多占宽度三分之一。上下边缘仍用于排序。
- 横向列间空隙单独解析为插入边界，覆盖完整空隙并避开源块；显示“放到两列之间并排成列”。只含一个块的列拖回原本位置时隐藏无效提示。
- 移动端堆叠列的空隙改按纵向距离寻址。
- 键盘对 callout / blockquote 首段的块识别与鼠标一致；结构不允许的兄弟交换/复制不会交给 schema fitter 自动改写。
- 删除列表最后一项同时删除空包装；将编号列表项拖到列或转换成列时保留其实际起始编号。
- 文档读取拒绝畸形节点；浏览器存储不可用时偏好设置不会阻断工作区加载；复制/删除菜单操作后焦点返回正文。

复查：17 种斜杠菜单动作在分割线后执行均得到有效文档。浏览器实际操作确认分割线后选择代码并输入、右侧中部并排、列间插入、左列内部抽出块、整次撤销，以及收起折叠标题的 Enter 行为。类型检查、生产构建和 diff 空白检查通过。本轮没有新增或运行自动测试套件。

## 2026-10-20 Notion 对齐：块逻辑、Markdown 输入与分栏

| 问题 | 原行为 | 修复 |
| --- | --- | --- |
| 拖拽排序误建分栏 | 单行块只有上下各约 6px 用于排序，中部整片都会“向右并排成列” | 按块的上下半区决定放在上方或下方；只有左侧 32px 窄条和右侧约 1/4（40–160px）才会建分栏 |

| 分栏内退格丢字 | 在右列开头按退格，会删字或把两列内容并到一起 | 有内容时不做任何操作；空块被删除，必要时一并移除空列，光标回到上一处文字 |
| 分栏后的段落被塞进分栏 | 在分栏行下方段落的开头按退格，该段落会变成右列中的一个新块 | 把文字接到最后一列最后一行的末尾；列表、引用、折叠块后的段落同样如此 |
| Tab 让光标离开编辑器 | 普通段落按 Tab，焦点跳到页面按钮 | Tab 不再离开编辑器：上方是列表或折叠块时，把当前段落缩进到其中，Shift+Tab 移回；代码块用两个空格缩进 |
| 拖出待办后列表被拆开 | 同类列表相邻时仍是两个节点，编号列表会从 1 重新编号 | `ListJoin` 在同一个撤销步骤内合并相邻的同类列表；显式重新编号的有序列表不合并 |
| 列宽拖动无效 | 按下拖动手柄时会改动分栏行的 class，ProseMirror 因此重绘该行，正在拖动的列视图被销毁 | 状态 class 改为放在 `body` 和列自身上；松手后焦点回到正文，Ctrl/Cmd+Z 可直接撤销 |
| 分栏下方的空白 | 每列底部固定占用一块“添加区块”按钮的高度 | 桌面端移除这块高度；点击较短列下方的空白处即可在该列添加块，手机端仍保留按钮 |

- Notion 的 `[] `（未勾选待办）。
- 中文标点模式下的 `＃ `、`》 `、`【】 `、`··· `、`1。 `、`－ `。
- 输入 ` ```语言 ` 后直接按 Enter 生成代码块。
- `[文字](链接)` 输入完成后转为链接：仅接受 http、https、mailto 或裸域名；以 `!` 开头的图片写法不转换。

## 2026-10-21 复制为纯文本的空行

问题：从日志复制到记事本、聊天软件等纯文本目标时，每行之间多出一个空行。所有块类型都会出现，因为纯文本按 Markdown 段落规则用空行分隔每个块；用户留的空行会变成三个空行，`snake_case`、`[Blocker]` 等还带有转义反斜杠，软换行带行尾空格。HTML 剪贴板（富文本目标）不受影响。

修复：纯文本与 Notion 一致，一行一个块，块之间不加空行；空段落保留为一个空行；只转义会变成格式的 `*` 和反引号；软换行不带行尾空格。同一列表项内的第二段仍用空行分隔，以便粘回后结构不变。粘贴 Markdown 时，没有缩进的普通行会结束上方的列表或引用（不再被当作续行），每行成为独立的块。`contentText` 摘要同样使用单换行。回归测试覆盖复制文本与粘回结构，并在 Chromium 中读取系统剪贴板验证。
